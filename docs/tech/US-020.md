## Tóm tắt giải pháp
- Hồ sơ công khai nằm ở **bảng 1-1 mới `teacher_profiles`** (khoá chính `user_id`), không thêm cột vào `users`. Bảng gom ảnh, `headline`, `bio`, trạng thái đồng ý và cờ trang chủ. `users.bio` và `users.avatar_path` ngừng dùng từ T36 và bị xoá ở release sau (ADR-005).
- **Một chốt duy nhất** quyết định API công khai có được trả ảnh/bio hay không: `App\Support\PublicTeacher`. Mọi API công khai (`GET /courses/{slug}`, `GET /home/teachers` và các API sau này) chỉ được xuất `avatar_url`/`bio` qua chốt này. Chưa đồng ý thì hai trường này là `null`.
- Bằng chứng đồng ý ghi vào bảng **`consents`** đã có (type mới `teacher_public_profile`, kèm phiên bản câu chữ, IP, UA), giữ suốt vòng đời tài khoản. `teacher_profiles` chỉ lưu trạng thái hiện tại để truy vấn nhanh. `audit_logs` vẫn ghi đủ 5 action theo AC20.
- **Giới hạn 6 người** dùng mutex bằng cách khoá **mọi dòng `teacher_profiles` theo `user_id` tăng dần** trong transaction rồi mới đếm. Bảng chỉ vài trăm dòng nên chi phí không đáng kể, và cách này đúng ở READ COMMITTED mà không cần gap lock.
- **Cache:** Laravel không cache gì. API công khai phản ánh dữ liệu ngay, chỉ gửi `Cache-Control: public, max-age=60` + `ETag` như `/courses`. Độ trễ ≤ 60 giây đến từ lớp cache phía trước (Next Data Cache `revalidate: 60`). Cấm thêm `Cache::remember` cho hai endpoint này, vì như vậy sẽ cộng dồn độ trễ.

## Mô hình dữ liệu

### Bảng mới `teacher_profiles` (1-1 với `users`, chỉ giáo viên)
| Cột | Kiểu | Null | Default | Index/FK | Ghi chú |
|---|---|---|---|---|---|
| user_id | bigint unsigned | N | | **PK**; FK users `cascadeOnDelete` | Dòng tạo lười ở lần ghi đầu tiên (`insertOrIgnore` ngoài transaction) |
| headline | varchar(120) | Y | | | Văn bản thuần 1 dòng, rule `PlainText` |
| bio | varchar(600) | Y | | | Văn bản thuần nhiều dòng (rule `PlainText(allowNewlines: true)`), đã chuẩn hoá `\r\n` → `\n`, trim; chuỗi rỗng lưu `NULL` |
| avatar_path | varchar(255) | Y | | | `{uuid}.webp` trên disk `uploads` (do `ImageUploadService` sinh) |
| public_consent_at | datetime | Y | | | Khác NULL = **đang đồng ý**. Rút đồng ý thì set NULL |
| public_consent_version | varchar(20) | Y | | | Phiên bản câu chữ đã đồng ý (`config('teacher_profile.consent_version')`). NULL khi chưa/đã rút |
| public_consent_withdrawn_at | datetime | Y | | | Lần rút gần nhất (hiển thị cho GV; lịch sử đầy đủ ở `consents`) |
| show_on_homepage | boolean | N | false | IX `ix_teacher_profiles_homepage` (show_on_homepage, homepage_order) | Chỉ Admin/QLT đổi |
| homepage_order | smallint unsigned | Y | | (trong IX trên) | 1..999; NULL xếp sau. CHECK `chk_teacher_profiles_homepage_order` |
| profile_updated_by | bigint unsigned | Y | | FK users `nullOnDelete` | Người sửa nội dung gần nhất (ảnh/headline/bio), dùng cho "Chỉnh sửa gần nhất bởi" (BR6) |
| profile_updated_at | datetime | Y | | | |
| created_at, updated_at | datetime | | | | |

CHECK, đặt tên tường minh theo quy ước data-model §5:
- `chk_teacher_profiles_homepage_order`: `homepage_order IS NULL OR homepage_order BETWEEN 1 AND 999`
- `chk_teacher_profiles_consent_version`: `public_consent_at IS NULL OR public_consent_version IS NOT NULL`

`$fillable` của `TeacherProfile` chỉ gồm `headline` và `bio`. Các cột `avatar_path`, `public_consent_*`, `show_on_homepage`, `homepage_order`, `profile_updated_*` chỉ được đổi bằng `forceFill` trong `TeacherProfileService` (S17).

### Bảng sửa
| Bảng | Thay đổi |
|---|---|
| `users` | Ngừng đọc/ghi `bio`, `avatar_path` (bỏ `bio` khỏi `$fillable`). **Chưa xoá cột** trong T36. Xoá ở release sau (backlog T36-1). Thêm quan hệ `teacherProfile()` (hasOne) và `taughtCourses()` (belongsToMany qua `course_teacher`) |
| `consents` | Không đổi schema. Thêm giá trị `ConsentType::TeacherPublicProfile` = `teacher_public_profile`, `granted_by=self`, `channel=web_form`, `policy_version` = phiên bản câu chữ. Đồng ý → INSERT. Rút → `UPDATE ... SET revoked_at = now() WHERE user_id=? AND type='teacher_public_profile' AND revoked_at IS NULL` |
| `audit_logs` | Không đổi schema. Action mới ở mục Audit bên dưới |

### Index & truy vấn dùng
- `GET /home/teachers` đi từ `teacher_profiles` (≤ vài trăm dòng), join `users` theo PK, `EXISTS` trên `course_teacher` IX(user_id) + `courses` PK. Không cần index mới ngoài `ix_teacher_profiles_homepage` (index này chủ yếu để ghi rõ ý đồ, vì bảng nhỏ nên quét toàn bảng cũng rẻ).
- `GET /courses?teacher_id=` dùng `course_teacher` IX(user_id) đã có (subquery `whereIn courses.id`).

**Ước lượng khối lượng:** `teacher_profiles` khoảng 50 dòng sau 1 năm, ≤ 200 dòng sau 3 năm. `consents` thêm khoảng 1–3 dòng/giáo viên/năm. `audit_logs` thêm vài chục dòng/tháng. Không đáng kể.

## Kế hoạch migration
1. `create_teacher_profiles_table` (T36): tạo bảng, FK, IX, 2 CHECK (`DB::statement` có tên, `down()` drop CHECK rồi drop bảng). Bảng mới nên không ảnh hưởng zero-downtime.
2. Cùng migration, sau khi tạo bảng: `INSERT INTO teacher_profiles (user_id, bio, avatar_path, created_at, updated_at) SELECT id, NULLIF(TRIM(bio),''), avatar_path, NOW(), NOW() FROM users WHERE role='giao_vien' AND (bio IS NOT NULL OR avatar_path IS NOT NULL)`. Dự kiến 0 dòng (hiện chưa có đường ghi), tối đa vài chục dòng nên không cần command chia lô. **Không** chép đồng ý: mọi hồ sơ cũ đều chưa đồng ý (BR5). `bio` cũ > 600 ký tự thì cắt bằng `LEFT(..., 600)` (DBA xác nhận).
3. Code T36 chuyển hẳn sang `teacher_profiles` trong cùng release. Release sau (backlog T36-1): migration xoá `users.bio`, `users.avatar_path` sau khi xác nhận không còn chỗ nào đọc (grep + PHPStan). Tách release theo quy tắc "không xoá cột đang dùng trong cùng release".

  S->>DB: INSERT IGNORE teacher_profiles(user_id) (ngoài transaction)
  S->>DB: BEGIN
  S->>DB: SELECT user_id FROM teacher_profiles ORDER BY user_id FOR UPDATE (mutex toàn bảng, PK tăng dần)
  S->>DB: SELECT ... WHERE user_id=? (đã khoá) ; nếu đã bật → COMMIT, 200, không audit

Admin thứ hai bị chặn ở câu `FOR UPDATE` đầu tiên. Khi được chạy tiếp, transaction đó đọc bản đã commit của admin thứ nhất, đếm đủ 6 và nhận 409. Tắt hiển thị (`false`) hoặc chỉ đổi thứ tự thì chỉ khoá dòng đích, không cần mutex.

### Ảnh đại diện
`storeWebp` (ngoài transaction, file mới) → transaction khoá dòng hồ sơ, `forceFill(avatar_path)`, ghi `profile_updated_*`, audit → sau commit xoá file cũ. Lỗi trong transaction thì xoá file mới (đúng mẫu `CourseService::update`). File mồ côi (tiến trình chết giữa hai bước) do `images:prune-orphans` dọn.

### Công khai `GET /home/teachers`
```sql
SELECT u.id, u.name, tp.headline, tp.bio, tp.avatar_path
FROM teacher_profiles tp JOIN users u ON u.id = tp.user_id
WHERE tp.show_on_homepage = 1 AND tp.public_consent_at IS NOT NULL
  AND tp.avatar_path IS NOT NULL AND tp.bio IS NOT NULL
  AND u.role = 'giao_vien' AND u.status = 'active' AND u.anonymized_at IS NULL
  AND EXISTS (SELECT 1 FROM course_teacher ct JOIN courses c ON c.id = ct.course_id
              WHERE ct.user_id = u.id AND c.status = 'published' AND c.deleted_at IS NULL)
ORDER BY tp.homepage_order IS NULL, tp.homepage_order, u.id
LIMIT :homepage_max;
-- câu 2 cho ≤ 6 id ở trên: số khóa + các lớp
SELECT ct.user_id, COUNT(DISTINCT c.id) AS courses_count, GROUP_CONCAT(DISTINCT c.grade_level ORDER BY c.grade_level) AS grades
FROM course_teacher ct JOIN courses c ON c.id = ct.course_id
WHERE ct.user_id IN (...) AND c.status = 'published' AND c.deleted_at IS NULL
GROUP BY ct.user_id;
```
Tổng cộng 2 câu, không N+1. Kết quả vẫn đi qua `PublicTeacher` (lớp kiểm thứ hai về đồng ý).

## Thứ tự khoá
- Đoạn mới, độc lập với chuỗi thương mại: **`users` → `teacher_profiles` (theo `user_id` tăng dần) → `consents`**.
  - Toggle trang chủ: khoá toàn bộ `teacher_profiles` theo PK.
  - Sửa nội dung, ảnh, đồng ý: chỉ khoá 1 dòng `teacher_profiles` (rồi tới `consents`).
  - `erase` (T34): khoá `users` trước rồi mới tới `teacher_profiles`.
  - Không luồng nào khoá `teacher_profiles` rồi mới khoá `users`.
- `StaffAccountService::changeRole`/`lock` không đụng `teacher_profiles` (BR9 giữ nguyên cờ), nên không đổi T33.

- `/courses?teacher_id=`: subquery theo IX(user_id), danh mục chỉ vài trăm khóa.
- Mutex toàn bảng chỉ dùng khi bật hiển thị (thao tác hiếm của admin), giữ khoá vài ms.

## Rủi ro & giả định
1. **SWR của Next Data Cache.** `revalidate: 60` theo kiểu stale-while-revalidate: lượt xem đầu tiên sau một khoảng không có truy cập có thể vẫn nhận bản cũ, sau đó mới làm mới. Khi truy cập đều thì trễ ≤ 60 s; trang vắng có thể hiện ảnh đã rút đồng ý cho đúng 1 lượt xem. API thì phản ánh ngay. Nếu PO cần chặt tuyệt đối: FW9 dùng `cache: 'no-store'` cho riêng `/home/teachers` (rẻ, mỗi lượt render trang chủ 1 call), còn trang chi tiết khóa thì phải có cơ chế xoá cache (ngoài phạm vi). **Cần PO chọn (mục cuối).**
2. **Đổi hành vi `GET /courses/{slug}`.** Mọi giáo viên hiện có sẽ trả `avatar_url`/`bio` = `null` cho tới khi tự đồng ý. Thực tế hiện mọi giá trị đã là null, nên không mất gì trên UI. Test T10 (`CatalogTest`, `CatalogQaTest`) phải sửa theo.
3. **Slot bị chiếm bởi người không hiện.** Giáo viên bị khoá hoặc đã đổi vai trò vẫn giữ `show_on_homepage` (BR9) và **vẫn tính vào 6**. Màn admin phải liệt kê cả họ (lý do `account_locked`/`not_teacher`) và cho tắt. Nếu không, có thể kẹt slot.
4. **Đổi câu chữ đồng ý.** Đổi `consent_version` thì đồng ý cũ **vẫn có hiệu lực** (mặc định). Nếu PO/pháp chế muốn bắt đồng ý lại, chỉ cần thêm điều kiện `public_consent_version = current` vào `PublicTeacher` và query, không đổi schema.
5. **Pháp lý.** Ảnh chân dung là dữ liệu cá nhân. Đồng ý có bằng chứng (`consents`) và rút được. Thời hạn giữ bằng chứng sau khi rút, và câu chữ, do pháp chế V2 rà (story đã ghi là không chặn).
6. **Bio chặn `<`/`>`.** Như mọi trường văn bản thuần khác của dự án, `bio` chặn cả `<`/`>` đứng riêng. Giáo viên muốn viết "điểm > 9" sẽ nhận 422. Chấp nhận để đồng nhất. Nới sau nếu có phản hồi.
