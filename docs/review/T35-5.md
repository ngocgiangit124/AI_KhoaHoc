# REVIEW: T35-5 (redis chạy user 999:999)
**Kết luận:** APPROVE (PASS) — không BLOCKER
**Phạm vi:** diff chưa commit `infra/production/docker-compose.yml`, `infra/production/README.md` · 2 file

## Tổng quan
Sửa đúng nguyên nhân gốc: bỏ đường root+chown của entrypoint (image redis chỉ chown khi `id -u` = 0), chạy thẳng 999:999, bỏ `cap_add` nên còn `cap_drop: ALL` thuần. Đã kiểm trên server thật. Không hồi quy bảo mật, mà còn giảm quyền.

## Đối chiếu 4 câu hỏi
1. Giả định root/cap CHOWN còn sót: trong `infra/production` (compose, deploy.sh, smoke/*, check-images.sh) không còn chỗ nào. deploy.sh chỉ `stat` mode file, không đụng thư mục redis. Chỉ còn tài liệu cũ (R1, R2 bên dưới).
2. Smoke: `docker-compose.smoke.yml` ghi đè volume thành `smoke-redis:/data` / `smoke-redis-video:/data`. Named volume rỗng được Docker khởi tạo từ `/data` của image (đã `chown redis:redis`), nên user 999 ghi được. Smoke vẫn chạy được, nhưng cũng chỉ là smoke đường volume, không bắt lỗi bind-mount (đã ghi trong README).
3. `conf/redis.conf`, `users.acl` 0400 owner 999 mount `:ro`: đọc được bằng 999. Smoke dùng 0644 nên đọc được. Redis không `CONFIG REWRITE`/`ACL SAVE` vào file ro, nên không phát sinh lỗi ghi.
4. Bảo mật: không hồi quy. Bỏ 3 cap, vẫn `no-new-privileges`. Dữ liệu `/srv/vitaminvui/redis` vẫn 0700, chỉ đổi owner sang 999 (README đã nêu `sudo -u nobody ls` phải bị từ chối). Lưu ý nhỏ: uid 999 trên host có thể trùng một user hệ thống, README đã có dòng `getent group 999` (nên thêm `getent passwd 999`).

## Phát hiện
### R1 [SHOULD] Tài liệu còn nói "cap_add tối thiểu cho redis"
- Vị trí: `docs/adr/ADR-008-dong-goi-trien-khai.md:290`, `docs/security/review-T35.md:30` (docs/review/T35-1.md là lịch sử, giữ nguyên).
- Đề xuất: ghi "mysql cap_add tối thiểu; redis chạy user 999:999, không cap_add" (hoặc thêm dòng điều chỉnh T35-5 vào mục "Điều chỉnh khi hiện thực" của ADR-008).

### R2 [SHOULD] Thiếu hướng dẫn nâng cấp cho server đã có thư mục redis owner root
- Vị trí: `infra/production/README.md` mục 3 (và phần nâng cấp/runbook).
- Vấn đề: server cũ (hoặc server đã cài một phần) có `/srv/vitaminvui/redis` root:root; sau khi đổi sang `user: 999:999` redis không mở được `/data` và lặp restart.
- Đề xuất: thêm một dòng: `chown -R 999:999 /srv/vitaminvui/redis [/srv/vitaminvui/redis-video]` TRƯỚC khi deploy bản compose mới; có thể thêm preflight trong `deploy.sh` (kiểm `stat -c %u` thư mục redis = 999, nếu không thì `die` kèm lệnh sửa).

### R3 [NIT] Lặp comment 3 dòng ở hai service; đưa vào một anchor/comment chung. Thêm `getent passwd 999` cạnh `getent group 999`.

## Gợi ý cho QA
- Trên Linux thật: `docker compose up` redis (và redis-video nếu bật) qua vài lần restart, `docker inspect` CapAdd rỗng, AOF ghi được trong `/data` (`ls -ln` owner 999), PONG đúng/WRONGPASS sai (đã làm trên server thật).
- Kiểm nâng cấp từ thư mục root:root (R2) có báo lỗi rõ.
