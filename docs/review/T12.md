## Tổng quan
Code module chắc tay: TUS tự viết đúng (khoá hàng, hồi offset khi 413, abort 422 sau commit), magic bytes trước ffprobe, Process mảng tham số + `-protocol_whitelist file` + `-format_whitelist` + `-f` khoá, route regex + realpath, HMAC `hash_equals`, CORS riêng, production guard, ranh giới module sạch (adapter không import `App\VideoLab`). Test bao đủ 5 case §3a.7. Vấn đề lớn nhất nằm ở cấu hình container worker: nhiều khả năng worker không bao giờ nhận được job.

## Phát hiện

### R1 [BLOCKER] worker-video khác prefix Redis với app → không nhận job, webhook không được xử lý
- Vị trí: `infra/docker-compose.yml` service `worker-video`, khối `environment` (không có `APP_NAME`/`REDIS_PREFIX`); đối chiếu `backend/config/database.php:157` (`prefix = env('REDIS_PREFIX', slug(APP_NAME).'-database-')`) và `backend/.env` có `APP_NAME=VitaminVui`.
- Vấn đề: worker mount `.env` bằng /dev/null nên `APP_NAME` mặc định `Laravel` → prefix `laravel-database-`, trong khi php/queue dùng `vitaminvui-database-`. Hậu quả: (a) `TranscodeVideoJob` đẩy vào `vitaminvui-database-queues:video` mà worker nghe `laravel-database-queues:video` → video kẹt status 1 mãi; (b) `SendVideoLabWebhookJob` do worker dispatch (TranscodeService::run/markFailed) đẩy vào prefix `laravel-` mà worker `queue` mặc định không đọc → webhook mất, chỉ còn `videos:check-stuck` (15 phút) bù. Suy từ code, chưa chạy container (không được recreate) → QA phải xác nhận.
- Đề xuất:
  ~~~yaml
  # worker-video.environment
  APP_NAME: VitaminVui
  REDIS_PREFIX: vitaminvui-database-   # phải khớp prefix app; ghi chú trong compose
  ~~~
  Thêm vào test/QA e2e: dispatch job từ container php, worker-video phải xử lý.

- Vị trí: `app/VideoLab/Services/MediaToolkit.php:30` và `:50` (`new Process($cmd, null, null, ...)` → env null = kế thừa toàn bộ env của worker, gồm `DB_PASSWORD`, `REDIS_PASSWORD`).
- Vấn đề: sandbox được thiết kế để ffmpeg bị khai thác cũng không lấy được bí mật; nhưng mật khẩu nằm trong env của tiến trình con. Tài khoản DB của worker lại là tài khoản app đầy đủ quyền.
- Đề xuất: truyền env sạch cho Process.
  ~~~php
  private function cleanEnv(): array

      return array_fill_keys(array_keys(getenv()), false) + ['PATH' => '/usr/local/bin:/usr/bin:/bin', 'HOME' => '/tmp'];
  }
  // new Process($cmd, null, $this->cleanEnv(), null, $timeout)
  ~~~
  Ghi backlog-v2: user MySQL riêng cho worker-video, chỉ quyền trên `vl_videos` (+ jobs/cache cần thiết).

### R3 [SHOULD] CDN truy vấn DB cho từng segment, không throttle
- Vị trí: `app/VideoLab/Http/Controllers/CdnController.php:23` (`Video::...->exists()` mỗi request .ts/.m3u8, 1 phút video ≈ 10 segment × số người xem).
- Đề xuất: bỏ truy vấn khi đã có token hợp lệ + file nằm trong `hls/{guid}/` (chỉ tồn tại sau khi rename lúc `finished`, vì `.work-*` không khớp route), hoặc cache `finished` 60s qua `Cache::remember`. Ở production nên bật `VIDEOLAB_ACCEL_REDIRECT` và `limit_req` Nginx cho `/videolab/cdn/`.

### R4 [SHOULD] Khoá suy ra từ APP_KEY áp dụng cho mọi môi trường ≠ production; chưa test production guard
- Vị trí: `config/videolab.php:14-16` (`env('APP_ENV') === 'production' ? null : derive`), `VideoLabServiceProvider.php:50`.
- Vấn đề: staging (hoặc `config:cache` chạy khi `APP_ENV` chưa là production, rồi cache chứa khoá suy ra) vẫn qua guard. Không có test nào cho `guardProductionConfig` (khoá <32 ký tự, thiếu, `public_url` http).
- Đề xuất: chỉ derive khi `in_array(env('APP_ENV'), ['local','testing'], true)`; guard áp dụng cho mọi env ngoài local/testing; thêm test (Pest, `app()->detectEnvironment` hoặc gọi trực tiếp provider) cho 3 nhánh throw.

### R5 [MINOR] Tệp mồ côi khi xoá/đổi trạng thái giữa chừng
- `ManagementController::destroy` (`:46`) xoá file+row nhưng worker đang transcode sẽ tạo lại `hls/{guid}/` (rename ở TranscodeService::encode) mà không còn dòng DB; `.work-{guid}` sót khi worker bị kill; `videolab:cleanup` không quét. Đề xuất: cleanup quét thư mục `hls/*`, `source/*`, `incoming/*` không có bản ghi và cũ > 24h; trong `run()` kiểm lại tồn tại bản ghi trước `rename`.
- Video kẹt status 1–3 khi job mất (flush Redis) không được cứu: nên để cleanup re-dispatch hoặc đánh dấu lỗi sau X giờ.

### R6 [MINOR] TUS: ghi thiếu không được khôi phục
- Vị trí: `TusUploadService.php:171-190` (`writeBody`): `fwrite` không kiểm giá trị trả về; lỗi đĩa đầy/ngoại lệ giữa chừng để file dài hơn `upload_offset` → mọi PATCH sau trả 409 vĩnh viễn (`:140`).
- Đề xuất: `if (fwrite($out, $buffer) !== strlen($buffer)) { ftruncate($out, $offset); abort(507); }` và `ftruncate` trong `finally` khi có ngoại lệ chưa commit.

### R7 [MINOR] Ghi chú vận hành production (đưa backlog-v2 / T26)
- Nginx allow-list `library/` dùng cả 10/8, 172.16/12, 192.168/16: sau Load Balancer private mọi request sẽ vào được (chỉ AccessKey còn chặn). Production phải allow IP app server cụ thể và có `real_ip`. Chưa có cấu hình production trong repo.
- Chữ ký IP của token CDN và `Location` của TUS (scheme) phụ thuộc `TRUSTED_PROXIES` đúng; sai → token ràng IP trả 403 hàng loạt hoặc Location `http://`.
- `worker-video` hard-code `APP_ENV: local`, `APP_KEY` không có: image production cần cấu hình riêng.
- Probe ffprobe không giới hạn kích thước stdout; so `Content-Type` TUS bằng `!==` (chặn tham số `; charset`) — chấp nhận được, nêu để biết.

## Gợi ý cho QA
- Bắt buộc kiểm end-to-end THẬT trên Docker: `docker compose build php worker-video && docker compose up -d worker-video`; tạo video qua API admin T11 → upload TUS bằng file mp4 thật (vài chunk 8 MB, thử cả > 2 chunk) → xem worker-video log nhận job (xác nhận R1) → status 4 → phát `playlist.m3u8` qua `video.localhost:8000` (cả `VIDEOLAB_ACCEL_REDIRECT=true`) → webhook đến api (kiểm `video_assets` ready không cần chờ check-stuck).
- Sandbox: `docker compose exec worker-video sh -c 'id; touch /x; cat /var/www/backend/.env; wget -T3 -qO- http://example.com; env | grep -i pass'` → non-root, ghi lỗi, .env rỗng, không ra Internet.
- Worker ro: xác nhận `queue:work` không lỗi ghi `bootstrap/cache`/`storage` (read_only + mount ro).
- File độc: mp4 giả `#EXTM3U`, mov có dref tới `/etc/passwd`, mkv/mp4 hỏng, 1080p/4K, video > 180 phút, file lớn tới sát `max_upload_mb`.
- TUS: kill client giữa PATCH rồi HEAD→resume; hai PATCH song song cùng offset; PATCH quá chunk 8 MB (Nginx 413 vs Laravel 413); đĩa đầy (R6).
- Xoá video lúc đang transcode (R5); kill worker lúc transcode → retry rồi `failed()`.
- Từ host: `curl video.localhost:8000/videolab/library/...` (local không bị chặn allow-list, chỉ còn AccessKey).
