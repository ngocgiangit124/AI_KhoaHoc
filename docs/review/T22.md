## Phát hiện
### R1 [Major] Command auto-submit không cô lập lỗi từng lượt
- Vị trí: `app/Console/Commands/QuizzesAutoSubmitExpiredCommand.php:28`
- Vấn đề: 1 lượt ném exception (deadlock hết 3 lần thử, dữ liệu lạ) làm cả lần chạy dừng; vì `orderBy('expires_at')` + `limit`, lượt lỗi luôn đứng đầu hàng đợi, mỗi phút lại chết ở đó và các lượt sau không bao giờ được tự nộp theo nền (chỉ còn làm lười khi người dùng mở lại).
- Đề xuất:
  ~~~php
  ->each(function (QuizAttempt $attempt) use ($service, &$done): void {
      try {
          $service->finalizeIfExpired($attempt);
          $done++;
      } catch (\Throwable $e) {
          report($e); // log id lượt, không log đáp án
      }
  });
  ~~~
  Thêm 1 test: một lượt lỗi không chặn lượt sau.

### R2 [Minor] phpstan: `started_at`/`expires_at` bị hiểu là string
- Vị trí: `app/Http/Resources/Quiz/AttemptInProgressResource.php:38-39` (và tương tự các resource khác); gốc ở `app/Models/QuizAttempt.php` docblock.
- Đề xuất: thêm `@property Carbon $started_at`, `@property Carbon|null $expires_at`, `@property Carbon|null $submitted_at` vào docblock model.

### R3 [Minor] Limiter `quiz` dùng chung cho start/index/show/submit
- Vị trí: `app/Providers/AppServiceProvider.php` (limiter `quiz`, 30/phút/người, không tách theo quiz).
- Vấn đề: FE gọi `show` khi tải lại/chuyển trang kết quả + index lịch sử có thể chạm 30/phút khi học nhiều quiz liên tiếp. Không phải lỗ hổng.
- Đề xuất: giữ, hoặc tách `GET` (vd 60/phút) khỏi `POST`. Tuỳ PO.

### R4 [Nit] Làm tròn thời gian
- `started_at`/`expires_at` là `dateTime` không phần thập phân, MySQL làm tròn micro giây (có thể lệch ±0,5 s so với `now()`); nằm trong ân hạn 30 s nên không ảnh hưởng. Chỉ cần biết khi test biên.

### R5 [Nit] `show()` đọc câu hỏi 2 lần khi lượt vừa bị tự nộp
- `QuizAttemptService::show` → `settle` → `questionsFor`, rồi `AttemptController::present` gọi `questionsFor` lại (1 query `whereIn` + eager, không N+1). Bỏ qua được.
